PRD: ACM Student Chapter Scroll-Journey
Website
Audience for this document: an AI coding agent that will build or extend the website. It is
written to be self-contained: all copy is included in the Content Spec, so no other file is
needed.
1. Goal
Build a single-page, scroll-driven website for the ACM student chapter. As the visitor
scrolls, a boy travels from home to college (walk, bus, metro, boat, college door). Each stop
of the journey reveals one section of the chapter's content. The finished site must be fast,
readable on phones, and easy for the chapter team to edit.
Success means: all copy in section 6 appears on the site, word for word; the journey
animation runs smoothly; and every section is reachable from the navigation.
2. Scope
In scope: the single scroll page, navigation, all content sections below, the Join and Notify
Me forms (front end only), a Team section at the end, responsive layout, accessibility
basics, a content file the team can edit.
Out of scope for v1: user accounts, a database, an admin panel, payments, a blog, dynamic
event loading from an API.
3. Recommended stack (defaults, change only if the project already
uses something else)
Vite + React (or plain HTML/CSS/JS if the existing site is static)
GSAP + ScrollTrigger for the journey; CSS for everything else
Illustrations as inline SVG or optimized WebP/PNG; no video
Tailwind or plain CSS with design tokens (see section 5)
Form handling through a placeholder endpoint or a free form service (Formspree,
Google Forms embed); keep it swappable

4. Journey map (proposed, adjustable)
The scene changes (bus, metro, boat) are the transitions between sections. Content
cards slide in over or beside the moving scene. The boy character moves along a path as
scroll progress changes.
5. Global requirements
Navigation: fixed top bar with links About, Events, Focus Areas, Vision, Mission, Team,
Join. Clicking a link scrolls to that stop and plays the journey up to it. Show a thin scroll-
progress bar.
Design tokens (define as CSS variables, tune after seeing the reference photo): one
display font and one body font; a background, a text color, one accent, one muted color;
spacing scale 8, 16, 24, 48, 96 px; light and dark values.
Responsive: design for 390 px wide first, then tablet and desktop. On small screens
simplify the journey (smaller scene, fewer layers) but keep the order of stops.
Performance: target Lighthouse performance 85+ on mobile; lazy-load images below the
first scene; animate only transform and opacity; keep total JS under about 300 KB
gzipped.
Accessibility: honor prefers-reduced-motion (no scroll-scrubbed animation, stack
sections normally); all text at least WCAG AA contrast; real headings in order; alt text on
every meaningful image; keyboard focus visible; forms with labels.

7. Content file (so the team can edit without touching components)
Create one file, content.json (or content.ts), with these top-level keys: site (chapterName,
tagline, established), hero, about, whatIsAcm, roadmap, events, focusAreas, vision,
mission, join, team, links. Components must read all text from this file; no copy hard-
coded in components.
8. Animation spec
One master GSAP timeline scrubbed by ScrollTrigger, with a labeled position per stop
(home, bus, metro, boat, college, door).
The boy moves along an SVG path; at each transport stop the scene background swaps
with a cross-fade or slide, and a vehicle element (bus, metro, boat) moves across.
Content cards enter with opacity and a short upward translate; each plays once, not on
every scroll.
Pin the scene during a stop only as long as its content needs (about 100 to 200 vh).
Refresh ScrollTrigger on resize; kill timelines on unmount.

2. Navigation links scroll to the right stop; the progress bar tracks scroll.
3. Stats counters animate once when in view.
4. Focus Areas cards show the correct status badge for each domain.
5. Notify Me and Join forms validate email and show the success messages.

7. With reduced motion on, the page is a plain stacked layout with all content readable.
8. Lighthouse mobile: performance 85+, accessibility 95+.
11. Build order for the AI
1. Scaffold the project and content.json with all copy from section 6.
2. Build static sections in order with the design tokens, no animation.
3. Add navigation, progress bar and the forms.
4. Add the scene layers and the master scroll timeline.
5. Add the Team reveal and the door transition.
6. Optimize, test the acceptance criteria, fix.
After each step, run the site and confirm it before moving on.
